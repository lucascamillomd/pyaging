# Pyaging 0.6.0 DNAm median fallback implementation plan

> For agentic workers, use superpowers:executing-plans or, if the user chooses delegation, superpowers:subagent-driven-development. Track work with the checkboxes below.

**Goal.** Give human CpG beta clocks a reproducible fallback for absent columns and prepare pyaging 0.6.0.

**Architecture.** Generate a compressed, package-local CpG lookup from the two GEO cohorts. Load it lazily in the shared alignment path for eligible clocks that lack their own reference vector.

**Tools.** Python, pandas, NumPy, pytest, uv, and Hatch.

**Spec.** [Approved design](../specs/2026-11-03-dnam-median-fallback-design.md).

## Global constraints

- Use Hannum 450K [GSE40279](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE40279) and BoA EPIC v2 [GSE246337](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE246337). Record exactly which files, samples, and preprocessing produced the reference.
- Use finite beta values in [0, 1]. Aggregate EPIC v2 replicate probes within each sample before taking the median across samples. Average the two medians with equal cohort weight when both exist.
- Preserve model references, supplied values, missing-feature reporting, and rejection of entirely missing inputs. Keep feature ranges and the fallback separate.
- Prediction must work offline after the clock weights are available. Use existing dependencies and keep source matrices out of the package.

## Review focus

- EPIC v2 replicates with different missingness patterns still contribute one beta per sample and CpG.
- A CpG with no usable values in either cohort has no entry. A measured median of zero is a valid entry.
- An existing reference vector may contain intentional zero or NaN values. Use the vector as provided.
- Some clocks have DNA methylation metadata but consume derived proxies or transformed features. Scope the lookup to eligible CpG beta inputs.
- A checkout can hide missing package data. Verify loading the table from an installed wheel outside the repository.

## 1. Generate and audit the reference table

Create `clocks/build_dnam_feature_medians.py`, `tests/test_dnam_feature_medians.py`, and the generated `src/pyaging/data/dnam_feature_medians.json.gz`. The resource contains schema version 1, a `features` object mapping canonical CpG IDs to beta values, and provenance for both cohorts.

- [ ] Resolve the exact processed beta files from the GEO records. Verify the platform, units, sample IDs, tissue, and whether BoA probe IDs are already collapsed. Record source URLs and SHA-256 hashes. If a usable processed file is unavailable, document the source gap and resolve it before producing the release table.
- [ ] Add failing tests for `compute_cohort_medians(beta: pd.DataFrame, *, epicv2: bool) -> pd.Series` and `combine_cohort_medians(hannum: pd.Series, boa: pd.Series) -> pd.Series`. For an EPIC v2 CpG with sample pairs (0.2, 0.8), (0.3, missing), and (0.7, 0.9), assert a median of 0.5. Assert that cohort medians 0.2 and 0.8 yield 0.5 even with unequal cohort sizes, single-cohort medians pass through, zero is retained, and all-invalid columns disappear.
- [ ] Run `uv run pytest -q tests/test_dnam_feature_medians.py` and confirm the new tests fail because the generator is absent.
- [ ] Implement those functions and a CLI accepting local Hannum and BoA input paths plus an output path. Parse the verified source layouts into sample-by-probe beta blocks, masking invalid values before aggregation. Use `pya.pp.epicv2_probe_aggregation(..., verbose=False)` and keep every suffix group in a single block. Compute each median using all valid samples in that cohort. Sort the final CpG keys and write deterministic gzip output with a fixed timestamp.
- [ ] Run the tests again. Generate the full resource and regenerate it to check that the hashes agree. Record sample counts, counts before and after filtering and aggregation, Hannum-only, BoA-only, and shared CpG counts, and independently spot-check one median in each coverage category against the input files.

## 2. Integrate the fallback into prediction

Modify `src/pyaging/predict/_pred_utils.py`, `tests/predict/test_input_and_batching.py`, and the missing-feature paragraph in `AGENTS.md`. Add a private cached `_load_dnam_feature_medians() -> dict[str, float]` that opens the Task 1 resource with `importlib.resources` and gzip.

- [ ] Inspect registered human DNAm artifacts without model references. Compare model metadata, actual input identifiers, and preprocessing contracts. Use those findings to define eligibility. Raw human CpG beta inputs qualify. Derived inputs, nonhuman models, and clocks that consume transformed CpGs do not. Use an explicit clock declaration or exception only if the existing fields cannot distinguish a real case.
- [ ] Add a failing alignment test with a supplied value of 0.2, an absent covered CpG with table value 0.6, and an absent uncovered CpG. Assert the aligned row equals [0.2, 0.6, 0.0]. Assert the same missing names, mask, and percentage as before. With a model vector containing zero and NaN for those absent probes, assert it wins for both. Add cases for an ineligible input contract, a complete input that never loads the table, and the existing error on entirely absent input. Use a small test table to isolate these cases from cohort revisions.
- [ ] Run `uv run pytest -q tests/predict/test_input_and_batching.py` and confirm the covered-probe case fails because it still gets zero.
- [ ] In `_align_features_into_obsm`, apply the model vector first. In its absence, use the packaged table for eligible missing CpGs, with zero for all other absent features. Read the table only when an eligible CpG is absent and inference can proceed. Keep fill values local to alignment. Log median and zero counts when the table supplies values.
- [ ] Run `uv run pytest -q tests/predict/test_input_and_batching.py tests/predict/test_cohort_transform.py tests/predict/test_feature_range_check.py`. Verify a representative eligible clock with complete input and compare predictions to the pre-change baseline.

## 3. Measure prediction effects

- [ ] Select independent beta matrices with enough observed model features to form complete-input baselines. Confirm sample independence from the two reference cohorts. Start with blood and include a nonblood dataset where a suitable matrix and clock overlap are available.
- [ ] Run paired predictions on identical masks with median fill and zero fill. Use fixed seeds for random masks at 5%, 10%, and 25% of model CpGs, and use a real array coverage mask where possible. Report clock, tissue, sample count, mask, fraction of absent probes covered by the table, and median and 95th percentile absolute prediction change from the complete-input baseline, in the clock's output units. For chronological-age clocks with age labels, report MAE against age separately. State any gaps in the held-out data.
- [ ] Save the input provenance, seeds, reproducible commands, and results in `docs/development/dnam-median-fallback-validation.md`. Review material worsening and its scope before marking the change ready for release.

## 4. Prepare 0.6.0 and verify the distribution

Modify `src/pyaging/__init__.py` and `CHANGELOG.md`. Update `uv.lock` only if uv reports a version-related lock change.

- [ ] Set `__version__ = "0.6.0"` with `make version VERSION=v0.6.0`. Hatch reads that field for distribution metadata. Document the three fallback levels, cohort sources, and applicability in the changelog.
- [ ] Run `uv lock --check`, `uv run pytest`, and `uv build`. Check the wheel and sdist for the compressed resource and confirm distribution metadata reports 0.6.0. Install the built wheel in a clean environment and, from outside the checkout, check the imported version and load the shipped table. Confirm a known covered CpG has the generated beta value.
- [ ] Review the final diff and verification results. Leave tagging and publishing for a separate release action.
