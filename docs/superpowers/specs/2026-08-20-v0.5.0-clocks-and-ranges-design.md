# pyaging v0.5.0 — Four blood-chemistry clocks + feature-range safeguard

**Date:** 2026-08-20
**Status:** Approved by Lucas (design conversation, 2026-08-20)

## Goal

Add four clinical/blood-chemistry aging clocks (kdmage, homeostaticdysregulation,
phenoagesaopaulo, linage2), introduce a package-wide out-of-range input safeguard
backed by a central feature-range registry with package-wide units, roll both out to all HuggingFace clock
repos tagged v0.5.0, and release pyaging 0.5.0.

## 1. New clocks

All four get a notebook in `clocks/notebooks/`, a `.pt` weight file, HF upload,
and catalogue metadata. Sex is passed as a `female` feature column
(1 = female, 0 = male), matching the package-wide harmonization in Section 2.

### kdmage (Klemera-Doubal Biological Age)

- Source: `kdm_nhanes()` in dayoonkwon/BioAge, run locally in R (R 4.3.1
  installed). Trained sex-specifically on NHANES III, ages 30–75, non-pregnant.
- Biomarkers (package default): `fev, sbp, totchol, hba1c, albumin, creat,
  lncrp, alp, bun` (+ `age`, `female`).
- Extracted parameters per sex: per-biomarker regression parameters (q, k, s)
  and s_ba2.
- Implementation: new `KDMAge` model class computing the KDM estimator in
  torch, selecting male/female parameter tensors row-wise by the `female` feature.
- Output unit: years.

### homeostaticdysregulation

- Source: `hd_nhanes()` in BioAge. Reference cohort: NHANES III ages 20–30,
  BMI < 30, non-pregnant, biomarkers within clinically acceptable ranges,
  sex-specific.
- Biomarkers (package default): `albumin, lymph, mcv, glucose, rdw, creat,
  lncrp, alp, wbc` (+ `female`).
- Extracted parameters per sex: reference means, SDs, and inverse covariance
  matrix.
- Implementation: new `HomeostaticDysregulation` model class computing the
  Mahalanobis distance after reference-standardization, returning the
  log-transformed score (BioAge `hd_log`).
- Output unit: log dysregulation score (NOT years) — stated in metadata notes.

### phenoagesaopaulo

- Source: `phenoage_calc()` refit on NHANES III (ages 20–84, SI units as in
  `phenoage_nhanes`) using the 6 PhenoAge biomarkers that remain after
  dropping creatinine, albumin, and alkaline phosphatase:
  `glucose (mmol/L), lncrp, lymph, mcv, rdw, wbc` (+ `age`).
- Same two-stage Gompertz form as PhenoAge: linear mortality score →
  PhenoAge conversion, but with the refit's own gamma/conversion constants
  (new postprocess entry; the original 1998/2018 constants do not apply).
- Implementation: `LinearModel` + new postprocess with refit constants.
- Not included in the blood-chemistry tutorial (per Lucas).

### linage2

- Source: Fong et al., "LinAge2: providing actionable insights and
  benchmarking with epigenetic clocks", npj Aging 11:29 (2025),
  doi:10.1038/s41514-025-00221-4 (CC-BY). Parameters from Supplementary
  Table 2 (parametrized version), Table 3 (sex-specific PC loadings),
  Table 4 (sex-specific Cox weights), plus the linAge2.R code archive from
  the article's Code Availability.
- Pipeline encapsulated in a new `LinAge2` model class: log transforms of
  designated parameters, outlier capping at 6 SD, robust z-scoring
  (median/MAD of the healthy 40–50yo reference, per sex), sex-specific PC
  projection, Cox-weight combination, mortality→biological-age conversion
  (mortality rate doubling time ≈ 7.8 y).
- Validation: reproduce the R script's BA for the paper's two example
  subjects (8881: BA 88.7; 9106: BA 64.4) within numerical tolerance.
- Features: ~60 clinical parameters + `female`, in the units used by linAge2.R
  (documented per feature via the safeguard's unit metadata).

## 2. Feature-range safeguard (central registry design)

### Ground-truth registry (in the package, not per-clock)

- New versioned file `src/pyaging/data/feature_ranges.json`: the package-wide
  ground truth mapping canonical feature name → `{unit, low, high}` with
  broad plausibility bounds (designed to catch unit errors and swapped
  columns, not to flag sick patients). One feature name = one unit,
  package-wide — this is what enforces unit consistency across clocks.
- High-dimensional omics features are NOT enumerated; modality rules apply
  by clock `data_type`:
  - Methylation (Illumina human/mammalian, RRBS): strict [0, 1] betas.
  - Count-based omics (RNA-seq, ATAC-seq, histone ChIP-seq): non-negative,
    plus an input-scale check — each such clock declares whether it expects
    integer counts or log-scale values (`input_scale`), verified per clock
    against its preprocessing during implementation; inference warns when
    the data's scale looks wrong (e.g. non-integers where counts are
    expected, or count-magnitude values where log is expected).
- Covariates: `age` bounded [0, 122.5] years; `female` must be 0 or 1.

### Per-clock metadata (lightweight)

- Clocks keep `self.features` (existing) and gain optional
  `self.feature_units` (per-feature unit strings, mainly for clinical
  clocks; derivable from data_type for omics) and optional
  `self.input_scale` for count-based clocks.
- Loading tolerates clocks without the new attributes (`getattr` fallback),
  so cached pre-v0.5.0 `.pt` files keep working.

### Inference-time check

- New step in `predict/_pred_utils.py` after feature assembly: looks up each
  clock feature in the registry (or applies the modality rule), NaN-safe
  count of out-of-range values; if any, logs a **warning** naming the
  offending features, expected range/unit, and percentage of values
  affected. Prediction always proceeds (warn-only).

### Feature-name harmonization (breaking changes)

- Sex feature: `female` everywhere, coded 1 = female, 0 = male. Existing
  clocks grimage, grimage2, pcgrimage, dnamfitage rename `Female` → `female`
  (coding already matches). New clocks (kdmage, homeostaticdysregulation,
  linage2) use `female` instead of source-native codings (NHANES gender 1/2
  is recoded during weight extraction).
- Age feature: lowercase `age` everywhere; same four clocks rename
  `Age` → `age`.
- Both renames documented as breaking changes in the v0.5.0 changelog.

### Rollout of clock-file changes

- One-off script (following `update_all_clocks.py` / `hf_repo_sync.py`
  patterns): download each `.pt`, apply feature renames + unit/scale
  metadata, re-save, re-upload; patch the corresponding notebooks
  ("Normal feature ranges" section in `template.ipynb` and per-clock
  sections) so future regeneration is consistent. Full notebook reruns are
  NOT required.

## 3. Rollout and release

- All 173 existing + 4 new HF repos re-uploaded and tagged **v0.5.0**
  (same flow as the v0.4.0 sync).
- Blood-chemistry unit convention: all clinical clocks share the existing
  `phenoage` SI convention (albumin g/L, creatinine µmol/L, glucose mmol/L,
  lnCRP on mg/dL, lymphocyte %, MCV fL, RDW %, ALP U/L, WBC 10³ cells/µL),
  extended consistently for kdmage (fev, sbp, totchol, hba1c, bun) and
  linage2 features; source coefficients are converted where their native
  units differ. The registry file is the single source of truth.
- `tutorials/tutorial_utils.ipynb` (search/cite/metadata tutorial) gains a
  section showing how to inspect a clock's feature units and normal ranges
  from the registry.
- `tutorials/tutorial_bloodchemistry.ipynb` updated to run `phenoage`,
  `kdmage`, `homeostaticdysregulation`, and `linage2` together on example
  data extended with `female` and the union of required biomarkers, and to
  demonstrate the range warnings. `phenoagesaopaulo` is excluded.
- Tests: unit tests for the four new model classes (including LinAge2
  example-subject validation and KDM/HD parity against BioAge outputs on
  sample data) and for the range-check warning path.
- Version bump to 0.5.0, docs/clock catalogue regeneration, single PR to
  main, PyPI release via existing Trusted Publishing workflow, HF sync.

## Decisions log

- Biomarker sets: BioAge package defaults verbatim (KDM keeps fev/sbp).
- Safeguard: warn-only; never blocks prediction.
- Ranges live in a central package registry (`feature_ranges.json`), keyed by
  canonical feature name; clocks carry only units/scale metadata (Lucas's
  proposal, 2026-08-20, superseding the earlier per-clock-ranges decision).
- DNAm betas: strict [0, 1]. Count omics: non-negative + int/log input-scale
  check. Clinical: broad plausibility bounds. age ∈ [0, 122.5]; female ∈ {0, 1}.
- Feature harmonization: `female` (1 = female, 0 = male) and lowercase `age`
  across all clocks, including renames in grimage, grimage2, pcgrimage,
  dnamfitage.
- One blood-chemistry unit convention package-wide (phenoage SI convention).
- All HF repos retagged v0.5.0.
- phenoagesaopaulo weights produced by me via local R + BioAge run.
- LinAge2 implemented from the provided paper PDF + its supplementary
  materials and code archive.
